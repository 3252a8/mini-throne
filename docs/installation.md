# Установка и обновления

## Для владельца Minishop

1. В админке откройте плагины → установку из репозитория.
2. Вставьте `https://github.com/3252a8/mini-throne`; ветку оставьте пустой.
3. Проверьте издателя `minishop-3252a8-dev` и отпечаток
   `0938230804a2b1438e905361e805c378e8b817c1fe018231e87ee96d8f9ca729`.
   Доверие издателю подтверждается один раз штатным интерфейсом Minishop.
4. Установите и включите пакет. Штатный менеджер применит новую генерацию плагинов.
5. Плагин сам скачает проверенный EXE из последнего GitHub Release. Первая загрузка
   занимает время; далее файл отдаётся с локального диска и поддерживает Range.

Пакет рассчитан на Linux x86_64 / Python 3.12 и Core revision
`67357d3cfad4a430bfd66fbb507ddad390e5eb73`. Для иной совместимости нужен проверенный
пакет: ограничения установщика намеренно не обходятся. Обновление ZIP отображается
в штатном менеджере плагинов. Сам плагин автоматически обновляет установщик клиента,
но не подменяет собственный код вне контроля администратора.

Никакой EXE вручную загружать на сервер не нужно. Постоянный кэш находится рядом с
`MINISHOP_PLUGIN_STORE`: обычно `/app/data/mini-throne/installers`. Доступ к GitHub
должен быть разрешён. При сбое сети или подписи остаётся предыдущий проверенный файл.
Сохраняются две последние версии; более старые удаляются спустя сутки.

## Инструкции и Subscription Page

В инструкциях Minishop приложение появляется в списке Windows. Кнопка скачивания
открывает страницу плагина с выдачей персонального EXE. Блок установки также доступен
в стандартной области расширений инструкций. Это работает и с локальной конфигурацией
инструкций, без необходимости менять Core.

После загрузки первого проверенного релиза плагин через Remnawave API добавляет
Mini Throne в Windows-приложения конфигураций Subscription Page. Другие приложения и
оформление сохраняются. Повторный запуск не создаёт дубликатов. Уже существующий пункт
Mini Throne не перезаписывается. При недостаточных правах панели вход и скачивание
в Minishop продолжают работать; повторная попытка выполняется через час.

На штатной Subscription Page используются общий EXE и кнопка
`mini-throne://import/{{SUBSCRIPTION_LINK}}`. Она открывает окно добавления подписки
и требует подтверждения пользователя. Авторизацию Minishop эта публичная страница
не создаёт. Адрес подписки с параметрами и закодированными символами сохраняется целиком.

Можно отключить изменение панели: `MINI_THRONE_SYNC_PANEL=false`.
До первого изменения сохраняется исходная конфигурация в
`/app/data/mini-throne/panel-backups/<uuid>.json`. Для отката сначала отключите
синхронизацию, затем восстановите нужную конфигурацию через API панели или её редактор.
Отключение плагина убирает его пункты внутри Minishop; ранее добавленный пункт на панели
остаётся до ручного удаления или восстановления резервной копии.

## Персональный EXE

Пользователь входит в Minishop, нажимает «Скачать для Windows» и запускает EXE,
сохранив имя. Содержимое файла одинаково для всех: в имени передаётся только адрес
инстанса и случайный одноразовый билет на 30 минут. Плагин ничего не компилирует.
Билет погашается атомарно; повторный запуск не меняет существующий вход.
Дубликаты скачивания с суффиксом ` (1)` поддерживаются. Для слишком длинного имени,
истёкшего билета или переименованного файла доступен вход через браузер.

Не передавайте персональный файл другим людям до погашения билета и не логируйте
`Content-Disposition`. Персональные ответы имеют `Cache-Control: private, no-store`.
Ссылка скачивания закреплена за версией EXE на всё время жизни билета.

## Клиент без Minishop

Скачайте [EXE](https://github.com/3252a8/mini-throne/releases/latest/download/Mini-Throne-Setup-x64.exe)
и откройте «Добавить подписку или сервер». Поддерживаются HTTP/HTTPS-подписки и
отдельные VLESS, VMess, Shadowsocks, Trojan, SOCKS и другие ссылки Throne.
Подписки обновляются, источники и выбор сохраняются. Удаление требует подтверждения.
Системный прокси и TUN находятся в настройках по шестерёнке; полные настройки Throne
открываются оттуда же. База профилей общая, соединение на время настройки приостанавливается.

## Обновления клиента

При запуске установленный клиент проверяет подписанный релиз GitHub. Загружает изменения
через blockmap, при невозможности частичной загрузки скачивает весь EXE и проверяет
подписанный хеш. Применяет готовое обновление автоматически, когда соединение не активно;
иначе кнопка установки остаётся в настройках. Окно полных настроек Throne также блокирует
автоматический перезапуск. Старые alpha.3–alpha.5 необходимо один раз обновить вручную:
в них канал обновлений был отключён.

## Выпуск версии

Измените версию в `desktop/package.json`, lockfile и классе плагина. Проверьте Core pin
в `release-config.json` и workflow. Опубликуйте dev на обоих зеркалах, затем один тег
`vX.Y.Z` — GitLab первым, GitHub вторым. GitHub Actions выполняет проверки, собирает EXE,
подписывает ZIP и метаданные, публикует GitHub Release и индекс `minishop-plugin.json` с
`packages/mini-throne.zip`. Коммит индекса имеет автора 3252a8 и публикуется на оба зеркала.
GitLab получает такую же запись релиза со ссылкой на файлы GitHub.

Локально: `npm ci`, `npm run check`, `npm run build`, `npm run check:runtime` в `desktop/`;
`python scripts/check-plugin.py` и `python scripts/build-minishop-plugin.py` в корне.
Для первой подготовки движка выполните `node scripts/prepare-runtime.mjs` в `desktop/`.
Ключи локально защищены Windows DPAPI; CI получает их только из GitHub Actions Secrets.
